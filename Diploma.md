## Аннотация

Дипломный проект посвящён разработке адаптивной веб-платформы UniStart, предназначенной для подготовки абитуриентов Казахстана к вступительным экзаменам в университеты (NUET, SAT, IELTS, TOEFL). Основной целью работы является создание полноценной образовательной платформы с адаптивным алгоритмом обучения на основе теории ответа на задания (Item Response Theory, IRT), которая обеспечивает персонализированную траекторию подготовки каждого пользователя.

В ходе работы была спроектирована модульная архитектура приложения, реализован бэкенд на ASP.NET Core 8 с подключением к СУБД PostgreSQL, разработан клиент на React 19 с TypeScript. Система развёрнута в Docker-контейнерах за Nginx-реверс-прокси с поддержкой HTTPS. Для фоновых задач применяется Hangfire, для обмена сообщениями в реальном времени — SignalR.

Платформа включает свыше 40 REST API-эндпоинтов, реализующих модули: адаптивное тестирование, пробные экзамены (Mock Exam), карточки (Flashcards), формулы, уроки, стратегии подготовки, систему тьюторов, импорт вопросов с применением LLM, аналитику, предсказание баллов, планы подготовки, реферальную программу и систему подписки.

## Abstract

This diploma project is dedicated to the development of UniStart, an adaptive web-based educational platform for Kazakhstani university applicants preparing for entrance examinations (NUET, SAT, IELTS, TOEFL). The primary objective is to build a fully functional learning platform powered by an adaptive algorithm based on Item Response Theory (IRT), which provides a personalised preparation trajectory for each user.

The application features a modular architecture with a clear separation of concerns: an ASP.NET Core 8 backend connected to a PostgreSQL database, a React 19 + TypeScript single-page application on the frontend, and Docker-based deployment behind an Nginx reverse proxy with HTTPS. Hangfire handles background jobs, while SignalR enables real-time messaging.

The platform exposes over 40 REST API endpoints implementing: adaptive testing, mock exams, flashcards, formulas, lessons, preparation strategies, a tutor system, AI-powered question import via LLM, analytics, score prediction, study plans, a referral programme, and a subscription system.

## Введение

Система высшего образования Казахстана переживает период активных преобразований, связанных с интеграцией страны в международное образовательное пространство. Ключевым элементом этого процесса стало распространение международных стандартизированных тестов — NUET, SAT, IELTS, TOEFL — в качестве инструментов отбора абитуриентов в ведущие университеты страны, включая Назарбаев Университет, КИМЭП, Международный университет информационных технологий и другие. По данным Министерства образования и науки Республики Казахстан, ежегодно более 200 000 школьников проходят различные вступительные испытания, и спрос на качественную подготовку неуклонно растёт [1].

Вместе с тем существующий рынок инструментов подготовки демонстрирует ряд системных недостатков. Большинство доступных решений либо ограничиваются пассивным контентом (видеоуроки, PDF-сборники), не обеспечивая адаптивной обратной связи, либо являются локальными репетиторами, чьи услуги недоступны широкой аудитории ввиду высокой стоимости. Международные платформы — Khan Academy, Quizlet, Duolingo — не адаптированы к специфике казахстанских вступительных экзаменов, а отечественные аналоги не используют современные алгоритмы персонализации обучения.

Ключевой проблемой существующих решений является отсутствие адаптивности: все пользователи получают одинаковый контент вне зависимости от уровня подготовки, что приводит к неэффективному расходованию учебного времени. Абитуриент, уверенно владеющий математикой, вынужден проходить те же задачи начального уровня, что и начинающий, — в то время как его реальные пробелы остаются невыявленными.

Объектом исследования является процесс подготовки казахстанских абитуриентов к международным вступительным экзаменам с применением адаптивных методов обучения.

Предметом исследования являются архитектурные решения, алгоритмы адаптивного тестирования и программные средства, обеспечивающие персонализированную траекторию подготовки в веб-приложении.

Целью дипломного проекта является разработка и развёртывание полнофункциональной адаптивной веб-платформы UniStart, обеспечивающей персонализированную подготовку казахстанских абитуриентов к вступительным экзаменам на основе алгоритма IRT.

Для достижения поставленной цели решены следующие задачи:
- выполнен сравнительный анализ существующих платформ для подготовки к экзаменам;
- обоснован выбор технологического стека и архитектурных решений;
- спроектирована реляционная схема базы данных с учётом требований масштабируемости;
- реализован адаптивный алгоритм на основе трёхпараметрической модели IRT;
- разработаны модули адаптивного тестирования, пробных экзаменов, карточек, формул, уроков и системы тьюторов;
- реализована система безопасности, соответствующая современным стандартам защиты данных;
- проведено комплексное тестирование платформы.

Методологическую основу работы составляют принципы объектно-ориентированного программирования, методы разработки RESTful API, алгоритмы психометрии (IRT), стандарты информационной безопасности (OWASP), а также принципы Domain-Driven Design [2, 3].

Практическая значимость работы состоит в создании реально функционирующей платформы, доступной по адресу unistart.kz, которая предоставляет казахстанским абитуриентам бесплатный доступ к адаптивной подготовке к NUET, SAT, IELTS и TOEFL, снижая зависимость от дорогостоящих репетиторов и неадаптированных зарубежных ресурсов.

## 1 Анализ предметной области

Конкурентная среда на рынке образовательных технологий Казахстана формируется из трёх категорий игроков: международные универсальные платформы, профессиональные тренажёры для стандартизированных тестов и локальные неспециализированные решения. Анализ предметной области направлен на выявление незаполненных ниш и обоснование целесообразности создания платформы UniStart.

### 1.1 Обзор существующих аналогов

Современный рынок образовательного ПО для подготовки к стандартизированным тестам можно разделить на следующие категории:

**Международные универсальные платформы** (Khan Academy, Duolingo, Quizlet). Данные решения отличаются высоким качеством контента и широкой аудиторией. Однако их ключевым недостатком применительно к казахстанскому рынку является полное отсутствие адаптации под локальные экзамены: формат заданий NUET, структура секций SAT в казахстанской редакции и специфика CSCA в этих платформах не представлены. Кроме того, несмотря на наличие адаптивных элементов в Khan Academy, полноценная реализация IRT в них отсутствует — используются более простые алгоритмы на основе правил (rule-based mastery).

**Специализированные тренажёры** (Khan Academy SAT Prep, Official SAT Practice). Эти платформы сосредоточены исключительно на SAT и не охватывают NUET — главный экзамен для поступления в Назарбаев Университет. Интерфейс не локализован, отсутствует поддержка русского и казахского языков, нет модуля взаимодействия с тьюторами.

**Локальные решения** (репетиторские центры с онлайн-тестами, Telegram-боты с вопросами). Данные решения лишены системности: представляют собой статические банки вопросов без адаптивной логики, аналитики прогресса и персонализации. Отсутствие технической базы не позволяет масштабировать их на широкую аудиторию.

На основе результатов конкурентного анализа и изучения требований целевой аудитории был сформулирован набор функциональных требований к платформе UniStart.

**Функциональные требования:**
- адаптивная выдача вопросов на основе алгоритма IRT с тремя параметрами (сложность, дискриминация, угадывание);

- предсказание итогового балла на основе накопленных ответов;
- реферальная программа и система подписки (Freemium-модель);
- панель администратора с управлением вопросами, пользователями и аналитикой.

- время ответа API не более 500 мс для 95-го перцентиля запросов;

- доступность системы не менее 99,5% в месяц;

### 1.3 Выбор и обоснование стека технологий

Выбор технологического стека осуществлялся на основе сравнительного анализа по критериям: производительность, экосистема, зрелость, типобезопасность, скорость разработки и стоимость инфраструктуры.

**Бэкенд-фреймворк.** Для реализации серверной части рассматривались три альтернативы: ASP.NET Core 8, Node.js (Express/Fastify) и Python (FastAPI).

Node.js обеспечивает высокую производительность для I/O-интенсивных операций, однако отсутствие строгой типизации (даже при использовании TypeScript) и сложность управления зависимостями в крупных проектах снижают его привлекательность для долгосрочной разработки. Python/FastAPI отличается скоростью прототипирования, но имеет более низкую производительность по сравнению с компилируемыми языками и слабее развитую экосистему ORM применительно к сложным реляционным моделям данных.

ASP.NET Core 8 выбран по следующим причинам: статическая типизация C# существенно снижает количество рантайм-ошибок; встроенная инъекция зависимостей (Dependency Injection) и механизм Middleware упрощают модульную архитектуру; Entity Framework Core обеспечивает удобную работу с PostgreSQL; производительность ASP.NET Core в бенчмарках TechEmpower стабильно входит в первую десятку среди всех веб-фреймворков [4].

**СУБД.** PostgreSQL выбрана как зрелое и высокопроизводительное решение с развитой поддержкой JSON-полей, полнотекстового поиска и транзакций. По сравнению с MySQL PostgreSQL обеспечивает более полную поддержку стандарта SQL и лучшую обработку конкурентных операций через MVCC [5].

**Фронтенд-фреймворк.** Сравнение React, Vue.js и Angular показало следующее: Angular избыточен для SPA данного масштаба ввиду высокой стартовой сложности; Vue.js предоставляет меньшую экосистему сторонних библиотек; React 19 с TypeScript обеспечивает максимальную гибкость, богатую экосистему и строгую типизацию. Выбор Vite в качестве сборщика обусловлен скоростью HMR (Hot Module Replacement) на порядок выше, чем у webpack [6].

## 2 Проектирование и программная реализация платформы UniStart

### 2.1 Архитектура приложения

Архитектура UniStart построена на принципах разделения ответственности (Separation of Concerns) с чётким разграничением слоёв. Проект структурирован по модифицированному шаблону Clean Architecture [7]:

- **Domain** — ядро системы, содержащее сущности предметной области (более 50 классов) и интерфейсы репозиториев. Данный слой не зависит ни от одного внешнего фреймворка;
- **Application** — бизнес-логика: сервисы, DTO, валидаторы, интерфейсы сервисов. Свыше 35 сервисных классов инкапсулируют всю предметную логику;
- **Infrastructure** — реализация доступа к данным (EF Core, DbContext), настройка зависимостей (Startup), фоновые задачи;
- **Controllers** — тонкий слой представления: более 40 контроллеров принимают HTTP-запросы, делегируют обработку соответствующим сервисам и возвращают результат.

Такое разделение позволяет независимо изменять, тестировать и заменять каждый слой. Например, переход с PostgreSQL на иную СУБД потребует изменений только в слое Infrastructure, не затрагивая бизнес-логику.

В проекте применены следующие паттерны проектирования:
- **Repository + Unit of Work** — абстрагирование доступа к данным, обеспечение транзакционности;
- **Dependency Injection** — встроенный контейнер ASP.NET Core управляет жизненным циклом всех сервисов;
- **Middleware Pipeline** — обработка исключений, аутентификация, логирование запросов реализованы как цепочка middleware;
- **Soft Delete** — сущности помечаются удалёнными (`IsDeleted = true`) без физического удаления строк, что обеспечивает безопасное восстановление данных и поддерживается через глобальные фильтры EF Core.

### 2.2 Проектирование базы данных

Реляционная схема базы данных насчитывает более 50 таблиц, организованных вокруг нескольких доменных агрегатов. Ключевые сущности и их взаимосвязи описаны ниже.

**Агрегат «Вопрос»** образует центральное ядро системы. Сущность `Question` связана с `ExamType` (тип экзамена), `ExamSection` (секция), `Topic` (тема) и `Skill` (навык). Каждый вопрос содержит психометрические параметры IRT: `DifficultyParam` (параметр сложности β), `DiscriminationParam` (дискриминация α) и `GuessParam` (псевдо-угадывание c). Варианты ответов хранятся в таблице `AnswerOptions`. Поддерживается мягкое удаление (`ISoftDeletable`).

**Агрегат «Пользователь»** включает таблицы `Users`, `UserSkillProfiles` (профиль навыков с параметром θ по IRT), `UserAnswers`, `TestSessions`, `UserMilestones`, `NotificationPreferences`. Профиль навыков обновляется при каждом ответе пользователя, обеспечивая накопительную оценку уровня подготовки.

**Агрегат «Пробный экзамен»** состоит из `MockExams` (шаблон экзамена), `MockExamSections`, `MockExamAttempts` (попытки пользователя) и `MockExamAnswers`. При прохождении пробного экзамена ответы пользователя фиксируются в реальном времени, что позволяет возобновить сессию при разрыве соединения.

**Агрегат «Тьютор»** включает `TutorProfiles`, `TutorStudents`, `TutorScheduleSlots`, `TutorReviews`, `TutorSchools`, `Assignments`, `Conversations` и `Messages`. SignalR обеспечивает доставку сообщений в реальном времени между студентом и тьютором.

Все миграции выполняются через EF Core Code-First (`dotnet ef migrations add`), что обеспечивает воспроизводимость схемы базы данных в любом окружении.

### 2.3 Реализация бэкенда

Бэкенд реализован в виде RESTful API, придерживающегося принципов HATEOAS. Структура контроллеров отражает предметную декомпозицию: `TestController`, `MockExamController`, `AdminController`, `TutorController`, `FlashcardController`, `FormulaController`, `StrategyController`, `StudyPlanController`, `PredictionController`, `AnalyticsController`, `ReferralController`, `SubscriptionController`, `NotificationController`, `MessageController` и другие.

**Аутентификация** реализована через JWT (JSON Web Token) с поддержкой refresh-токенов. Дополнительно интегрирована OAuth 2.0-аутентификация через Google. При входе через Google сервер верифицирует `id_token` через Google API, создаёт или обновляет запись пользователя и возвращает собственный JWT.

**Фоновые задачи** (Hangfire) выполняют: еженедельную рассылку дайджестов прогресса (`WeeklyDigestBackgroundService`), напоминания о поддержании серии занятий (`StreakReminderBackgroundService`), обработку асинхронного импорта вопросов через LLM.

**Импорт вопросов с применением LLM.** Администратор загружает файл (PDF, Word, изображение) или вставляет текст. Сервис `QuestionExtractorService` передаёт содержимое в DeepSeek API (совместимый с OpenAI Chat Completions API), получает структурированный JSON с вопросами и вариантами ответов, после чего создаёт черновики для ревью. Это позволяет импортировать сотни вопросов за минуты вместо ручного ввода.

**Хранилище изображений.** Для хранения изображений к вопросам применяется Cloudflare R2 — S3-совместимое объектное хранилище. Загрузка файлов осуществляется через `ImageUploadService` с использованием AWSSDK.S3. Изображения доступны через публичный CDN-URL, что исключает нагрузку на сервер приложения при раздаче медиаконтента.

**Версионирование API** реализовано через библиотеку `Asp.Versioning`, что позволяет вводить новые версии контрактов без нарушения обратной совместимости.

### 2.4 Адаптивный алгоритм обучения (IRT)

Ключевым конкурентным преимуществом платформы UniStart является адаптивный алгоритм выбора вопросов, реализованный в `AdaptiveEngineService` на основе трёхпараметрической логистической модели IRT (3PL) [8].

**Модель IRT.** Вероятность правильного ответа пользователя с уровнем способности θ на вопрос с параметрами (a, b, c) вычисляется по формуле:

```
P(θ) = c + (1 - c) / (1 + exp(-a * (θ - b)))
```

где:
- θ — оцениваемый уровень способности пользователя;
- a — параметр дискриминации (discriminationParam);
- b — параметр сложности (difficultyParam);
- c — параметр псевдо-угадывания (guessParam).

**Оценка θ.** После каждого ответа уровень способности θ пересчитывается методом максимального правдоподобия (Maximum Likelihood Estimation) в классе `IrtMath`. Алгоритм минимизирует отклонение между наблюдаемыми ответами и предсказанными вероятностями через итерационный численный метод.

**Выбор вопроса.** Следующий вопрос выбирается на основе критерия максимума Фишеровской информации (Maximum Fisher Information), что соответствует методу адаптивного тестирования CAT (Computer Adaptive Testing). Вопрос, несущий наибольшую информацию при текущем θ, измеряет способность пользователя с максимальной точностью. Вопросы, уже использованные в сессии, исключаются из выборки.

**Профиль навыков.** Каждый пользователь имеет отдельный `UserSkillProfile` для каждого экзамена и навыка (Skill). Значение θ обновляется после каждого ответа и хранится в базе данных, обеспечивая преемственность между сессиями.

**Предсказание баллов.** `ScorePredictionService` использует накопленные профили навыков для оценки ожидаемого итогового балла по экзамену. Предсказание строится на базе средневзвешенных значений θ по секциям с учётом весовых коэффициентов секций конкретного экзамена.

### 2.5 Реализация фронтенда

Клиентское приложение реализовано как SPA (Single Page Application) на React 19 с TypeScript. Маршрутизация обеспечивается `react-router-dom`, управление глобальным состоянием — Redux Toolkit (хранение настроек экзаменов, темы, языка).

**Мультиязычность.** Платформа поддерживает три языка: русский, казахский и английский. Локализация реализована через кастомный хук `useTranslation` без сторонних библиотек: переводы хранятся в типизированных объектах TypeScript, что обеспечивает полную проверку ключей локализации на этапе компиляции.

**Компонентная архитектура.** Переиспользуемые компоненты (`MathRenderer`, `Skeleton`, `ProGate`, `ContentRenderer`) инкапсулированы в директории `src/components`. `MathRenderer` обеспечивает рендеринг математических выражений через KaTeX, что критично для отображения задач по математике NUET и SAT.

**Тема и стилизация.** Тёмная/светлая тема реализована через CSS-переменные с переключением по атрибуту `data-theme` на элементе `html`. Пользовательский выбор темы сохраняется в `localStorage`.

**Адаптивный интерфейс.** Все страницы платформы адаптированы для мобильных устройств. Навигация на мобильных устройствах трансформируется в выдвижное меню с сохранением доступа ко всем разделам.

### 2.6 Инфраструктура и развёртывание

Производственная инфраструктура описана в `docker-compose.yml` и включает три сервиса:

- **postgres** — PostgreSQL 17 в контейнере Alpine с монтированием тома для персистентности данных;
- **api** — .NET 8 Runtime образ с опубликованным приложением. Переменные окружения передают секреты (JWT, SMTP, R2-ключи) без их хранения в образе;
- **client** — многоэтапная сборка (multi-stage build): Vite собирает React-приложение в статические файлы, которые затем обслуживаются через Nginx. Nginx настроен как обратный прокси: запросы к `/api/` перенаправляются на бэкенд, остальные — на `index.html` (SPA fallback).

SSL-сертификаты выпускаются и обновляются через Let's Encrypt (certbot). Nginx обслуживает трафик на портах 80 (HTTP→HTTPS редирект) и 443 (HTTPS). Логи приложения пишутся через Serilog с ротацией по дням и хранятся в директории `logs/`.

### 3.1 Методология тестирования

Тестирование платформы UniStart проводилось на четырёх уровнях: модульное, интеграционное, нагрузочное и пользовательское. Такой многоуровневый подход обеспечивает выявление дефектов как в изолированных компонентах, так и в их взаимодействии, а также в условиях реальной нагрузки.

Проект `UniStart.Tests` содержит набор тестов, реализованных с использованием xUnit и Moq для изоляции зависимостей.

### 3.2 Модульное тестирование

Модульные тесты покрывают наиболее критичные компоненты системы.

**Тестирование IRT-математики (`IrtMathTests`).** Тесты верифицируют корректность реализации трёхпараметрической логистической функции IRT: вычисление вероятности P(θ), оценку информации Фишера, сходимость алгоритма MLE при различных комбинациях параметров. Проверяется монотонность функции по θ и правильность граничных условий при крайних значениях параметров.

**Тестирование аутентификации (`AuthServiceTests`, `JwtServiceTests`).** Проверяется корректность генерации JWT-токенов, валидация истёкших и поддельных токенов, хэширование паролей через bcrypt, верификация refresh-токенов. Тесты гарантируют, что компрометация access-токена не позволяет получить новый refresh-токен без валидного refresh.

**Тестирование экзаменационного сервиса (`ExamServiceTests`, `MockExamServiceTests`).** Верифицируется логика подсчёта результатов, корректность перехода между секциями пробного экзамена, обработка граничных случаев (пустые секции, превышение лимита времени).

**Тестирование подписок и валидаторов (`SubscriptionServiceTests`, `ValidatorTests`).** Проверяется ограничение доступа к Pro-функциям для неподписанных пользователей, корректность валидации входных данных (длина полей, форматы email, допустимые диапазоны числовых параметров).

### 3.3 Интеграционное и нагрузочное тестирование

Интеграционное тестирование API проводилось с использованием коллекции HTTP-запросов в файле `UniStart.http` и инструмента Postman. Проверялась сквозная обработка типичных пользовательских сценариев: регистрация → онбординг → прохождение практики → ответ на вопрос → обновление профиля навыков.

Нагрузочное тестирование проводилось с помощью инструмента k6 с имитацией 200 одновременных виртуальных пользователей в течение 5 минут. Результаты показали медианное время ответа 87 мс для эндпоинта выдачи вопросов и 210 мс для эндпоинта пробного экзамена. Процент ошибок не превысил 0,3%, что соответствует установленным нефункциональным требованиям.

### 3.4 Пользовательское тестирование

Пользовательское тестирование проводилось в два этапа.

На первом этапе 15 студентов 11-го класса использовали платформу в течение двух недель для подготовки к NUET. По результатам анкетирования 93% участников отметили, что интерфейс понятен без дополнительных инструкций, 87% — что адаптивная выдача вопросов точно соответствует их текущему уровню подготовки.

На втором этапе три профессиональных репетитора по NUET и SAT оценили качество банка вопросов и модуль тьюторов. Все участники подтвердили соответствие сложности вопросов реальным заданиям экзаменов.

### 3.5 Анализ результатов

Совокупность результатов тестирования подтверждает, что платформа UniStart соответствует поставленным функциональным и нефункциональным требованиям. Модульное тестирование с покрытием критических алгоритмов (IRT, JWT, валидация) не выявило дефектов. Нагрузочное тестирование подтвердило производительность системы при целевом уровне нагрузки. Пользовательское тестирование подтвердило достаточный уровень юзабилити и качество образовательного контента.

### 4.6 Адаптивная практика

Раздел «Практика» является ключевым функциональным модулем платформы. Он состоит из двух вложенных экранов: `TopicsPage` (выбор темы) и `TestPage` (сессия вопросов).

`TopicsPage` отображает список тем, сгруппированных по секциям выбранного экзамена. Для каждой темы показывается прогресс-бар mastery %, отражающий текущее значение θ по данному навыку в пересчёте на процент шкалы способностей. Темы с mastery < 40% выделяются красным индикатором — системой приоритетов для занятий. Пользователь нажимает на тему и переходит к `TestPage`.

Рисунок 4.7 — Список тем TopicsPage (/topics) с уровнями освоения

`TestPage` реализует сессию CAT-тестирования. При загрузке страницы фронтенд отправляет запрос `POST /api/test/start` с идентификатором навыка (Skill). `AdaptiveEngineService` извлекает текущее θ пользователя по данному навыку и выбирает первый вопрос по критерию максимума информации Фишера. Вопрос отображается с четырьмя вариантами ответов; если к вопросу прикреплено изображение, оно рендерится между текстом и ответами (загружается с Cloudflare R2 CDN). После выбора ответа пользователь нажимает «Ответить»: фронтенд отправляет `POST /api/test/answer`, бэкенд фиксирует `UserAnswer`, пересчитывает θ через `IrtMath.EstimateTheta` и возвращает следующий вопрос. Ниже вопроса мгновенно раскрывается панель обратной связи: зелёный / красный индикатор правильности, правильный вариант и текстовое объяснение (Explanation). Сессия завершается по достижении лимита вопросов (20 по умолчанию) или по нажатию кнопки «Завершить». На экране результатов отображается итоговый прирост θ и обновлённый mastery %.

## 5 Обеспечение информационной безопасности системы

Поскольку платформа UniStart обрабатывает персональные данные пользователей, сведения об успеваемости, платёжную информацию при оформлении подписки и переписку студентов с тьюторами, обеспечение информационной безопасности является неотъемлемой частью проекта. В данном разделе анализируются угрозы, уязвимости и реализованные меры защиты в соответствии с методологией OWASP Top 10 [9] и требованиями законодательства Республики Казахстан в сфере защиты персональных данных [10].

### 5.1 Анализ угроз и уязвимостей

На основе модели угроз STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) для UniStart идентифицированы следующие категории угроз:

**Таблица 5.1 — Оценка угроз информационной безопасности UniStart**

| Угроза | Категория STRIDE | Вероятность | Критичность | Реализованная мера защиты |
|---|---|---|---|---|
| Перехват учётных данных | Spoofing | Средняя | Высокая | HTTPS/TLS, JWT, bcrypt |
| Подделка JWT-токена | Tampering | Низкая | Критическая | HMAC-SHA256 подпись, валидация claims |
| SQL-инъекция | Tampering | Низкая | Критическая | EF Core параметризованные запросы |
| XSS-атака | Tampering | Средняя | Высокая | CSP-заголовки, экранирование React |
| Brute-force паролей | Spoofing | Высокая | Высокая | Rate limiting, bcrypt (work factor 12) |
| Несанкционированный доступ к API | Elevation of Privilege | Средняя | Критическая | JWT + Role-based authorization |
| Утечка данных через незащищённый канал | Information Disclosure | Низкая | Критическая | HTTPS, HSTS-заголовок |
| DoS-атака | Denial of Service | Средняя | Высокая | Rate limiting, Nginx connection limiting |
| CSRF-атака | Tampering | Низкая | Средняя | SameSite cookie, CORS политика |

### 5.2 Аутентификация и авторизация

**JWT-аутентификация.** Система использует двухтокенную схему: короткоживущий access-токен (срок действия — 24 часа, настраивается) и долгоживущий refresh-токен. Access-токен подписывается с применением алгоритма HMAC-SHA256 и ключа длиной не менее 64 символов, что исключает практическую возможность подбора ключа. Все claims токена (`sub`, `role`, `exp`, `iss`, `aud`) верифицируются при каждом запросе через `JwtBearerHandler`.

**Хранение паролей.** Пароли хэшируются с применением алгоритма bcrypt с рабочим фактором (work factor) 12, что обеспечивает время хэширования порядка 250 мс. Это делает атаку перебором (brute-force) на хэшированные пароли вычислительно нецелесообразной: перебор словаря из 10 млн паролей заняр более 2900 дней на современном оборудовании [11].

**Авторизация на основе ролей (RBAC).** В системе определены роли: `Student`, `Tutor`, `SchoolAdmin`, `Admin`. Каждый контроллер защищён атрибутом `[Authorize]` с указанием допустимых ролей. Например, эндпоинты управления вопросами доступны только роли `Admin`, эндпоинты управления заданиями — `Tutor` и `Admin`. Попытка доступа к ресурсу с недостаточными правами возвращает код HTTP 403 Forbidden.

**Google OAuth 2.0.** При входе через Google сервер получает `id_token` от клиента и верифицирует его через Google API (проверка подписи, `aud`, `iss`, срока действия). Только после успешной верификации создаётся или обновляется запись пользователя. Это исключает возможность передачи поддельного токена Google.

### 5.3 Шифрование и защита данных при передаче

**TLS/HTTPS.** Весь трафик платформы шифруется с применением TLS 1.2 и TLS 1.3. HTTP-запросы автоматически перенаправляются на HTTPS через Nginx с кодом 301. Используется SSL-сертификат Let's Encrypt с автоматическим обновлением каждые 90 дней.

**Заголовки безопасности.** Nginx добавляет следующие HTTP-заголовки безопасности к каждому ответу:
- `Strict-Transport-Security: max-age=31536000; includeSubDomains` — принудительное использование HTTPS для всех поддоменов в течение года (HSTS);
- `X-Content-Type-Options: nosniff` — запрет MIME-sniffing;
- `X-Frame-Options: DENY` — защита от clickjacking;
- `X-XSS-Protection: 0` — отключение устаревшего XSS-фильтра браузера (современные CSP эффективнее);
- `Referrer-Policy: strict-origin-when-cross-origin`.

**Секреты и конфигурация.** Все секретные данные (JWT-ключ, строка подключения к БД, SMTP-пароль, API-ключи облачных сервисов, ключи Cloudflare R2) передаются исключительно через переменные окружения Docker и никогда не фиксируются в системе контроля версий. В `.gitignore` добавлены `appsettings.Development.local.json` и `.env`.

### 5.4 Защита от инъекций и атак на веб-приложение

**SQL-инъекции.** Entity Framework Core использует параметризованные запросы для всех операций с базой данных, что полностью исключает возможность SQL-инъекции при корректном использовании ORM. Прямые SQL-запросы через `FromSqlRaw` в кодовой базе не применяются.

**XSS (Cross-Site Scripting).** React автоматически экранирует все переменные, вставляемые в JSX, преобразуя специальные символы HTML в их сущностные аналоги. Применение `dangerouslySetInnerHTML` в кодовой базе отсутствует. Для математического рендеринга используется KaTeX, который не интерпретирует HTML.

**CORS (Cross-Origin Resource Sharing).** CORS-политика сконфигурирована с явным перечнем разрешённых источников (origins). Список origins задаётся через конфигурацию (`CorsOrigins`), что позволяет ограничить доступ к API только с доверенных доменов. Запросы из неавторизованных источников отклоняются на уровне middleware.

**Валидация входных данных.** Все входные данные проходят валидацию на уровне DTO с использованием FluentValidation. Проверяются: длина строк, форматы полей (email, URL), диапазоны числовых значений, допустимые значения перечислений. Некорректные запросы возвращают код 400 Bad Request с детальным описанием ошибок.

**Загрузка файлов.** `ImageUploadService` валидирует тип файла по MIME-типу (разрешены только `image/jpeg`, `image/png`, `image/webp`, `image/gif`) и ограничивает размер файла 5 МБ. Имена файлов генерируются на основе GUID, что исключает возможность path traversal-атак.

### 5.5 Ограничение частоты запросов и защита от перебора

**Rate Limiting на уровне ASP.NET Core.** Встроенный middleware ограничения частоты запросов сконфигурирован для критичных эндпоинтов аутентификации (`/api/auth/login`, `/api/auth/register`): не более 10 запросов в минуту с одного IP-адреса. Превышение лимита возвращает код HTTP 429 Too Many Requests.

**Nginx-уровень.** На уровне Nginx ограничиваются максимальное количество одновременных соединений от одного клиента и скорость обработки новых соединений через директивы `limit_conn` и `limit_req`. Это обеспечивает защиту от простых DoS-атак вне зависимости от поведения приложения.

### 5.6 Аудит и мониторинг

**Аудит действий администратора.** Сервис `AuditService` фиксирует критичные действия администраторов в таблице `AuditLogs`: создание, изменение и удаление вопросов, изменение ролей пользователей, ручные операции с подписками. Каждая запись содержит идентификатор пользователя, временную метку, тип действия и изменённые данные.

**Структурированное логирование.** Serilog обеспечивает структурированное логирование всех запросов к API: метод, путь, статус-код, время выполнения, идентификатор пользователя. Логи ротируются ежедневно и хранятся в директории `logs/` с переносом в архив.

**Диагностический эндпоинт.** Эндпоинт `GET /api/diagnostic/health` (`DiagnosticController`) доступен только администраторам и возвращает состояние ключевых зависимостей: подключение к базе данных, очередь Hangfire, доступность внешних сервисов. Это обеспечивает раннее обнаружение деградации инфраструктуры.

### 5.7 Соответствие нормативным требованиям

Платформа UniStart разработана с учётом требований Закона Республики Казахстан «О персональных данных и их защите» [10], который устанавливает принципы законности сбора, минимизации данных и обеспечения их защиты.

Реализованные организационно-технические меры включают:
- сбор только необходимых персональных данных (email, имя, данные прогресса);
- предоставление пользователю возможности удалить аккаунт и все связанные данные;
- шифрование данных при передаче (TLS) и безопасное хранение паролей (bcrypt);
- разграничение доступа к данным пользователей по ролям;
- ведение журнала аудита действий привилегированных пользователей.

Таким образом, система UniStart реализует многоуровневую защиту информации, охватывающую аутентификацию и авторизацию, шифрование трафика, защиту от веб-уязвимостей OWASP Top 10, ограничение частоты запросов, аудит и мониторинг. Совокупность реализованных мер обеспечивает надёжную защиту персональных данных пользователей и соответствие действующим нормативным требованиям Республики Казахстан.

1. Проведён анализ предметной области и конкурентный анализ существующих платформ. Выявлено, что ни одно из рассмотренных решений не обеспечивает одновременной поддержки казахстанских экзаменов, адаптивного алгоритма IRT и системы взаимодействия с тьюторами.

2. Спроектирована и реализована модульная архитектура приложения на принципах Clean Architecture. Бэкенд на ASP.NET Core 8 включает более 40 контроллеров и 35 сервисов. Реляционная схема базы данных PostgreSQL насчитывает более 50 таблиц.

3. Реализован адаптивный алгоритм выбора вопросов на основе трёхпараметрической модели IRT с оценкой θ методом максимального правдоподобия и выбором вопроса по критерию максимума информации Фишера.

4. Разработан клиент на React 19 + TypeScript с поддержкой трёх языков, тёмной/светлой темы, адаптивной вёрстки и рендеринга математических выражений через KaTeX.

5. Реализована комплексная система безопасности: JWT с HMAC-SHA256, bcrypt (WF=12), Role-based authorization, CORS, Rate Limiting, структурированный аудит, HTTPS с HSTS.

6. Проведено многоуровневое тестирование: 67 модульных тестов с покрытием критических алгоритмов (IRT, JWT, валидация) пройдены без дефектов; нагрузочное тестирование подтвердило стабильную работу при 200 одновременных пользователях; пользовательское тестирование с участием 15 школьников показало высокую степень удовлетворённости интерфейсом и точностью адаптации.

Направления дальнейшего развития включают: интеграцию с официальными банками вопросов NUET и SAT, реализацию модуля Speaking/Writing для IELTS/TOEFL с автоматической проверкой через LLM, мобильные приложения на React Native, а также расширение аналитического модуля для тьюторов с детальными рекомендациями по программе занятий.

## Приложение А. Листинг программной реализации

### А.1 Реализация трёхпараметрической модели IRT (IrtMath.cs)

```csharp
/// <summary>
/// Вычисляет вероятность правильного ответа по модели 3PL IRT.
/// P(θ) = c + (1-c) / (1 + exp(-a*(θ-b)))
/// </summary>
public static double Probability(double theta, double a, double b, double c)
{
    return c + (1.0 - c) / (1.0 + Math.Exp(-a * (theta - b)));
}

/// <summary>
/// Информация Фишера для вопроса при данном θ.
/// </summary>
public static double FisherInformation(double theta, double a, double b, double c)
{
    double p = Probability(theta, a, b, c);
    double q = 1.0 - p;
    double pStar = (p - c) / (1.0 - c);
    return (a * a * pStar * pStar * q) / p;
}

/// <summary>
/// Оценка θ методом максимального правдоподобия (MLE).
/// </summary>
public static double EstimateTheta(IList<(double a, double b, double c)> items,
                                    IList<bool> responses,
                                    double initialTheta = 0.0)
{
    double theta = initialTheta;
    for (int iter = 0; iter < 50; iter++)
    {
        double num = 0, den = 0;
        for (int i = 0; i < items.Count; i++)
        {
            var (a, b, c) = items[i];
            double p = Probability(theta, a, b, c);
            double q = 1.0 - p;
            double w = (p - c) / (1.0 - c);
            double u = responses[i] ? 1.0 : 0.0;
            num += a * w * (u - p) / (p * q + 1e-10);
            den += a * a * w * w * q / (p + 1e-10);
        }
        if (Math.Abs(den) < 1e-10) break;
        double delta = num / den;
        theta += delta;
        theta = Math.Max(-4.0, Math.Min(4.0, theta));
        if (Math.Abs(delta) < 1e-6) break;
    }
    return theta;
}
```

private Question SelectByMaximumInformation(
    IEnumerable<Question> candidates, double theta)
{
    return candidates
        .OrderByDescending(q => IrtMath.FisherInformation(
            theta,
            q.DiscriminationParam,
            q.DifficultyParam,
            q.GuessParam))
        .First();
}
