## Что сделали

- Создать MVP+ адаптивной платформы для подготовки к SAT/TOEFL/NUET
- Реализовать базовую функциональность тестирования с адаптивным движком
- Добавить систему отслеживания прогресса и повторения ошибок
- Улучшить UX через тёмную тему, анимации и адаптивность
- Построить систему аутентификации с JWT

### За счёт чего продвинулись

#### Архитектурные решения
- **Clean Architecture** — чёткое разделение на слои (Domain → Application → Infrastructure → API), что позволяет легко тестировать и модифицировать компоненты независимо
- **CQRS-подобный подход** — разделение команд (submit answer) и запросов (get questions), упрощающий масштабирование
- **Entity Framework Core** — code-first миграции для быстрой итерации схемы БД без ручного SQL

#### Технологический стек
- **.NET 8 + ASP.NET Core** — современный бэкенд с отличной производительностью и поддержкой
- **React 19 + TypeScript** — строгая типизация предотвращает ошибки на этапе компиляции
- **Redux Toolkit** — предсказуемое состояние приложения, удобный DevTools для отладки
- **PostgreSQL 17** — надёжная СУБД с поддержкой сложных запросов и индексов
- **Vite** — мгновенная пересборка при разработке (HMR < 100ms)

#### Адаптивный движок (v1)
- **Алгоритм подбора сложности** — анализирует историю ответов пользователя и выбирает вопросы оптимальной сложности
- **Skill profiling** — отслеживание уровня по каждому навыку отдельно (Reading, Writing, Math, Critical Thinking)
- **Spaced repetition** — приоритизация вопросов с ошибками для повторного изучения
- **Правила**: уровень < 40 → Easy, 40–70 → Medium, ≥ 70 → Hard; верный ответ +5, неверный −3

#### Качественная база данных
- **30 вопросов** с продуманной структурой:
  - SAT Reading & Writing: 6 вопросов (Main Idea, Grammar, Vocabulary)
  - SAT Math: 9 вопросов (Linear Equations, Geometry, Quadratic, Data Analysis)
  - TOEFL: 5 вопросов (Academic Reading, Lecture Comprehension)
  - NUET: 10 вопросов (Algebra, Problem Solving, Logical Reasoning, Argument Analysis)
- **Детальные объяснения** — каждый вопрос содержит развёрнутое объяснение правильного ответа
- **Три уровня сложности** — Easy/Medium/Hard для каждой темы

### Этап 5: Продвинутый адаптивный движок (v2) 🧠

**Цель**: Перейти от простых правил (пороги 40/70, +5/−3) к модели, которая учитывает множество факторов и точнее определяет уровень студента.

#### 5.1 Item Response Theory (IRT)
- [ ] Реализовать **модель IRT** (1PL или 2PL) для калибровки вопросов:
  - Каждому вопросу назначается параметр сложности `b` (из статистики ответов)
  - Для 2PL — добавляется параметр различимости `a`
- [ ] Добавить поля `DifficultyParam` и `DiscriminationParam` в сущность `Question`
- [ ] Алгоритм оценки уровня: **Maximum Likelihood Estimation (MLE)** или **Expected A Posteriori (EAP)** вместо линейных +5/−3
- [ ] Оценка θ (theta) — латентный уровень способности студента по шкале
- [ ] Миграция и пересчёт параметров вопросов по историческим данным

#### 5.2 Мультидименсиональное профилирование
- [ ] Перейти от единого skill level к **вектору компетенций** по каждому топику
- [ ] Граф зависимостей между темами (напр. "Linear Equations" → "Quadratic Equations")
- [ ] Учитывать **давность ответов** — кривая забывания Эббингхауза для каждого навыка
- [ ] Confidence interval для оценки уровня — показывать пользователю "уровень 65 ± 8"

#### 5.3 Адаптивный выбор вопросов
- [ ] **Computerized Adaptive Testing (CAT)** — выбирать вопрос с максимальной информативностью (Fisher information)
- [ ] Ограничения выбора: не повторять вопросы, баланс тем, exposure control
- [ ] A/B тестирование: сравнить CAT vs текущий алгоритм по метрикам обучения

### Этап 6: Персональный план подготовки 📅

**Цель**: Автоматически генерировать и адаптировать индивидуальный план подготовки к конкретной дате экзамена.

#### 6.1 Настройка профиля цели
- [ ] UI: пользователь задаёт **целевой экзамен**, **дату экзамена**, **целевой балл**
- [ ] Новая сущность `StudyGoal` (UserId, ExamTypeCode, TargetDate, TargetScore, CreatedAt)
- [ ] Расчёт доступного времени: `daysUntilExam`, `recommendedHoursPerDay`

#### 6.2 Генерация плана
- [ ] Алгоритм распределения тем по дням на основе:
  - **Приоритет слабых зон** — наибольший вес темам с низким mastery
  - **Зависимости между темами** — сначала базовые, потом продвинутые
  - **Spaced repetition** — повторение через интервалы (1, 3, 7, 14 дней)
  - **Баланс нагрузки** — равномерное распределение по дням с учётом сложности
- [ ] Новая сущность `StudyPlan` (Id, UserId, GoalId, GeneratedAt, Entries[])
- [ ] `StudyPlanEntry` (PlanId, Date, TopicId, RecommendedMinutes, Type: New/Review/Practice)
- [ ] API `POST /api/study-plan/generate` — генерация плана
- [ ] API `GET /api/study-plan/today` — задания на сегодня
- [ ] API `PUT /api/study-plan/complete/{entryId}` — отметка выполнения

#### 6.3 Динамическая адаптация плана
- [ ] **Перерасчёт плана** после каждой сессии:
  - Тема освоена хорошо? → уменьшить будущие сессии для неё
  - Тема идёт плохо? → добавить дополнительные повторения
  - Пользователь пропустил день? → перераспределить нагрузку
- [ ] Уведомления: "Сегодня рекомендуем: Algebra (20 мин) + Grammar Review (15 мин)"
- [ ] Недельный обзор: выполнено/запланировано, отклонение от плана, рекомендации

### Этап 7: Прогнозирование результата на экзамене 📊

**Цель**: На основе данных о подготовке предсказать, какой балл студент получит на реальном экзамене, и показать, что нужно улучшить.

#### 7.1 Модель прогнозирования
- [ ] **Маппинг θ → балл экзамена**: преобразование латентного уровня IRT в шкалу реального экзамена:
  - SAT: 400–1600 (Math 200–800, EBRW 200–800)
  - TOEFL: 0–120 (Reading 0–30, Listening 0–30, Speaking 0–30, Writing 0–30)
  - NUET: собственная шкала
- [ ] Учитывать распределение вопросов по секциям и их вес в финальном балле
- [ ] **Confidence interval**: прогноз "SAT 1280 ± 60 (с вероятностью 80%)"
- [ ] Регулярный пересчёт прогноза после каждой тестовой сессии

#### 7.2 UI прогноза
- [ ] Виджет "Прогнозируемый балл" на главной странице — большой, заметный
- [ ] График динамики прогноза по датам
- [ ] Разбивка по секциям: "Math: ~720, Reading: ~560 — Reading нужно подтянуть"
- [ ] Сравнение с целевым баллом: "До цели 1350 осталось ~70 баллов, рекомендуем фокус на Reading"

#### 7.3 Рекомендации по улучшению
- [ ] Автоматический анализ: "Чтобы набрать +50 баллов, сфокусируйтесь на: Grammar (+20), Data Analysis (+15), Vocabulary (+15)"
- [ ] Приоритизация по ROI: какие темы дадут наибольший прирост балла при наименьших усилиях
- [ ] Сценарий "Что если": "Если улучшить Grammar с 45% до 80%, прогноз вырастет на ~40 баллов"

## Технический стек

| Компонент | Технология |
|-----------|------------|
| Backend | .NET 8 + ASP.NET Core |
| Frontend | React 19 + TypeScript + Vite |
| Database | PostgreSQL 17 |
| ORM | Entity Framework Core 8 |
| Auth | JWT (HMAC-SHA256) + BCrypt |
| State | Redux Toolkit |
| Styling | CSS Custom Properties (dark/light) |
| API Docs | Swagger / Swashbuckle |
