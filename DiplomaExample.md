2 слайд
Чтение и анализ журналов событий (лог-файлов) – важная часть работы большинства IT-специалистов. Данные журналов событий являются важным аспектом устранения неполадок в системе, а также выявления источников кибератак. 
Целью дипломного проекта является разработка анализатора журнала событий операционной системы Windows и систем управления базами данных MS SQL Server и MariaDB. 
Приложение, разрабатываемое в рамках дипломного проекта позволит быстро и комфортно произвести анализ журнала событий, формируемого средствами аудита данных систем.

3 слайд
Для достижения поставленной цели было необходимо решить следующие задачи:
произвести анализ предметной области;
определить функциональность разрабатываемого приложения;
осуществить выбор программных средств реализации;
разработать приложение, реализующее определенные функции в полном объеме.

4 слайд
В качестве исходных данных для работы разрабатываемой системы было решено выбрать журналы событий операционной системы Windows и систем управления базами данных MS SQL Server и MariaDB. В дальнейшем планируется расширить перечень используемых систем.

5 слайд
В ходе анализа предметной области были рассмотрены следующие аналоги: Screaming Frog Log File Analyser, Elastic Stack, SysTools SQL Log Analyzer.
Полученные на основе проведенного анализа выводы будут использованы при разработке анализатора журналов событий в рамках данного дипломного проекта.

6 слайд
Для разрабатываемого анализатора журналов событий были определены следующие функции:
сбор и сохранение информации о событиях из журналов событий ОС Windows, СУБД MS SQL Server и MariaDB;
группировка и выборка информации о событиях из базы данных по определенным признакам;
представление данных в виде различного рода таблиц, графиков и диаграмм;
экспорт таблиц, графиков и диаграмм;
отправка сообщений по электронной почте для уведомления ответственных работников о найденных событиях.

10 слайд
Для использования приложения пользователь должен иметь учетную запись. Для пользователей приложения предоставлено две роли: «Пользователь» и «Главный администратор». Роль «Пользователь» предоставляет возможность использования всего функционала приложения: добавление и получение событий, отправка сообщений. Роль «Главный администратор» позволяет добавлять и изменять данные всех таблиц базы данных (используется для добавления поддержки новых систем и журналов), создавать учетные записи пользователей.
На данном слайде изображено окно входа в приложение. После успешного входа появится главное окно, которое также представлено на слайде.

11 слайд
Для добавления событий в базу данных необходимо нажать кнопку «Добавить новые логи в БД». Далее следует выбор системы, события которой подлежат добавлению и выбор журнала, если система имеет несколько различных журналов. После выбора системы и журнала появляется окно для выбора файла с событиями, которое представлено на данном слайде.

12 слайд
Для получения событий из базы данных нужно нажать кнопку «Выборка». Если до этого не настроить фильтр выбор событий, приложение получит все события, хранящиеся в базе данных. После нажатия на «Настроить фильтр» начинается настройка фильтра в следующем порядке: выбор даты начала и конца, выбор требуемых систем, их журналов (если их количество больше одного), выбор серьезностей событий.
После нажатия «Выборка» приложение получит события из БД и заполнит таблицы и графики всех разделов. Это такие разделы, как: «Общие сведения», «Графики», «Деятельность пользователей», «Базы данных», «Таблицы».

13 слайд
Также после нажатия кнопки «Выборка» в разделах, которые имеют таблицу, становится доступной кнопка «Экспортировать таблицу в Excel». Пример экспортированного документа представлен на данном слайде.
В приложении есть как автоматическая отправка сообщений, так и ручная. Автоматическая отправка срабатывает после нажатия кнопки «Выборка», при наличии в полученном списке событий критичных событий. В таком случае пользователю предоставляется выбор – отправить сообщение или нет, если почта подключена. Если нажать «Нет», то отправка не произойдет. Если же нажать «Да», сообщение, содержащее критичные события и запрос к БД для их получения отправится всем пользователям с ролью «Главный администратор» и установленной почтой.
Для ручной отправки сообщений по электронной почте необходимо нажать кнопку «Отправить сообщение». Для отправки необходимо указать получателей письма и тему сообщения. Прикрепление файлов и текст сообщения не являются обязательными. При нажатии «Прикрепить файл» откроется окно выбора файла, файл может быть любого формата. Полностью составленное сообщение представлено на слайде. Если все необходимые поля заполнены, то по нажатию кнопки «Отправить сообщение» начнется его отправка.
