Введение

В современном мире научно-технологический прогресс становится фактором, значительно меняющим виды преступлений и способы борьбы с ними. Поскольку физическое ограбление становится всё менее обоснованным, ввиду снижающейся популярности наличных денег и материальных ценностей, в эпоху цифровизации единственным способом обогащения за счёт чужого несчастья становится похищение средств с аккаунта этого человека: обманом заставить его передать ценность в руки злоумышленника, либо же, используя различные уязвимости, самостоятельно завладеть электронными счетами.
Основным противником злоумышленников, защищающим средства и аккаунты людей, являются криптоаналитики, разработчики ПО, архитекторы систем безопасности и прочие специалисты, отвечающие за защищённость цифровых каналов связи. Благодаря ним, запросы между устройством пользователя и сервером, обрабатывающим очередной платёж, остаются защищёнными от мошенников, которые, в ином случае, смогли бы перехватить и/или изменить данные в целях личного обогащения.
Современная криптография для подавляющего большинства людей остаётся своеобразным «чёрным ящиком»  достаточно сложной структурой, в которую не хочется погружаться и достаточно того, что она просто работает как нужно. Сложность данной дисциплины достаточно сильно поднимает порог вхождения в криптографию, соответственно, снижая количество потенциальных специалистов, а также качество знаний о методах защиты данных среднестатистического пользователя. Применение элементов «геймификации» [1] при обучении криптографическим алгоритмам [2, 3] позволит охватить более широкую аудиторию и донести необходимую информацию в упрощённом варианте, при этом не потеряв качества доносимой информации.
Объектом исследования является обучение основным криптографическим алгоритмам людей, как связанных с цифровой безопасностью, так и средних пользователей интернета [4].
Предметом исследования являются игровые механики, а также способы программной реализации интерактивного симулятора в игровом движке Unity.
Целью дипломного проекта является разработка многоуровневого игрового симулятора «CrypteX», который предназначен для обучения базовым методам шифрования и их уязвимостей.
Задачи, необходимые для достижения поставленной цели:
 выполнить сравнительный анализ существующих программных решений;
 обосновать выбор программных инструментов, а также архитектуры приложения;
 придерживаться основных принципов гейм-дизайна при разработке;
 разработать сценарий и логику 15-ти игровых уровней, для более широкого охвата различных алгоритмов;
 провести тестирование игрового процесса.
Методологической основной работы являются методы системного анализа, принципы ООП и стандарты в области проектирования архитектуры приложений [5, 6].
Практическая значимость работы заключается в реализации ПО, позволяющего автоматизировать обучение и проверку знаний пользователей, связанным с освоением криптографических алгоритмов. Внедрение данного ПО позволит использовать интерактивность проекта для повышения вовлечённости и наглядности процесса обучения, по сравнению с устаревшими аналогами, такими как текстовые задачи и тесты.
Практическая польза для ТОО «Farabi travel agency» заключается в подготовке сотрудников к возможным киберугрозам. Сотрудники, которые знают как устроены алгоритмы защиты данных с меньшей вероятностью допустят различные ошибки, приводящие к утечке или потере критически важных данных. 1 Анализ предметной области

Компании малого и среднего бизнеса, которые взаимодействуют с конфиденциальной информацией клиентов, на сегодняшний день являются одной из приоритетных целей для злоумышленников. Исходя из этого, появляется потребность в инструментах, которые позволяют повысить уровень цифровой грамотности сотрудников, сводя к минимуму человеческий фактор при цифровых атаках.
Обучение основам криптографии в современных реалиях требует комплексного подхода, включающего в себя различные методы и источники знаний. Одним из способов улучшения качества восприятия информации является геймификация. Использование игровой формы обучения при правильном гейм-дизайне [7] и левел-дизайне позволяет передать гораздо большие объёмы информации в обход выгорания и перегруженности мозга. Формат игры позволяет человеку в интерактивной форме понять основные принципы и логику действий, позволяющих пройти тот или иной уровень, что делает игры одним из лучших методов обучения.
Главным минусом такого подхода является повышенная трудозатратность и, иногда даже, невозможность создания эмуляции на должном уровне. Создание игр  невероятно трудозатратный процесс, который может занимать месяцы и годы работы десятков и сотен человек, в зависимости от масштаба проекта. Соответственно, в большинстве случаев создание полноценной игры большого масштаба с целью обучения не является целесообразной тратой финансовых и временных ресурсов. Однако создание относительно небольших игровых проектов  задача значительно более тривиальная, и, в зависимости от потребностей при обучении, может быть использована в качестве основного или вспомогательного метода обучения.
Также, поскольку игры являются искусством в том или ином виде, такой вид обучения при открытом распространении может значительно повлиять на заинтересованность тематикой массового пользователя. В этом случае игра превращается в культурный феномен, который распространяет идею, заложенную при создании, на очень обширную аудиторию. Это позволяет колоссально увеличить количество потенциальных специалистов, которые могут заниматься созданием и обслуживанием существующих криптографических систем и протоколов, связанных с обеспечением защиты данных.
Разработка игрового симулятора CrypteX проводилась на базе туристического агентства «ТОО Farabi travel agency».

1.1 Обзор существующих аналогов

В текущих реалиях рынок интерактивного игрового ПО в сфере информационной безопасности условно можно разделить на несколько групп:
 развлекательные симуляторы (Hacknet, Grey Hack);
 профессиональные платформы (TryHackMe, HackTheBox);
 образовательные простые игры (Cyber Security Game).
Отличительной особенностью развлекательных симуляторов является их упор на увлекательный геймплей  создание уникального игрового опыта. Основными минусами таких проектов считаются недостоверность, высокая упрощённость и стремящийся к нулю потенциал к обучению. В развлекательных симуляторах главная цель  развлечь игрока и оставить от игры положительное впечатление.
Профессиональные платформы  это симуляторы, а также настоящие виртуальные машины, созданные как тренажёры для создания профессиональных кадров. Главным недостатком такого ПО является чрезвычайно высокий порог вхождения.
Образовательные простые игры являются антиподом профессионального ПО  это максимально упрощённые, часто примитивные симуляторы настоящих систем, которые чаще всего создаются с целью заинтересовать тематикой лиц школьного и дошкольного возраста. Главным недостатком таких игр является избыточная примитивность и частичная недостоверность предоставляемого контента.

1.2 Постановка целей и задач проектирования

На основе проведенного анализа существующих программных решений, целью дипломного проекта является разработка интерактивного симулятора «CrypteX». Проект направлен на повышение эффективности освоения криптографических методов студентами и различными профильными специалистами за счет использования технологий геймификации и иммерсивного обучения, что позволяет визуализировать сложные математические процессы и закрепить теоретические знания на практике.
Для реализации поставленной цели были выделены следующие основные задачи:
 спроектировать структуру 15 игровых уровней, которые должны охватить спектр алгоритмов от классических шифров (шифр Цезаря, Атбаш) до современных стандартов шифрования (RSA) [8];
 реализовать качественную диалоговую систему для погружения игрока в сюжет, чтобы повысить уровень вовлечённости пользователя в игру;
 создать архитектуру классов и скриптов на языке C# для реализации игровых механик;
 внедрить в игру классические механики гейм-дизайна для снижения порога вхождения (удобный UI/UX, добавление фоновой музыки и FX-звуковых эффектов, меню выбора уровней, меню паузы и т.д.);
 провести тестирование игровых механик на реальных пользователях, провести анализ обратной связи.


1.3 Выбор и обоснование стека технологий

Для разработки игрового симулятора был выбран современный движок Unity [9], который использует ЯП C# [10]. Выбор движка обоснован следующими факторами:
 ЯП   скрипты для данного движка пишутся на C#. Использование этого ЯП позволяет программировать, используя парадигму ООП, опыт работы с которой позволяет лучше понимать устройство работы современного ПО. Также C# является компилируемым ЯП со строгой статической типизацией, что сводит к минимуму возможные проблемы с дебаггингом на этапе рантайма. Движок Unity строится на идее «Всё есть объект», ровно так же, как и ЯП C#, что значительно упрощает использование движка Unity при разработке;
 гибкость Unity. Несмотря на то, что на Unity написан далеко не один успешный проект (например, хоррор Phasmophobia, симулятор выживания Rust, симулятор выживания Subnautica, метроидвания Hollow Knight и т.д.), в большинстве своём Unity считается движком для инди-разработчиков (от англ. independent  независимый), которые создают часто недорогие игры и проекты с инновационными игровыми механиками, зачастую задавая новые тренды в игровой индустрии. Данная особенность появилась вследствие чрезвычайной гибкости самого движка  в нём можно создать всё, что угодно: от математической визуализации тессеракта, до невероятно реалистичного крупнобюджетного проекта, от симулятора фермера до Tetris. Такая свобода креатива является ключевым фактором при выборе движка и в случае данного дипломного проекта. В отличие от своего главного конкурента  Unreal Engine, Unity является не таким громоздким, имеет значительно более простой UI и лучше работает с 2D-графикой;
 наличие собственной VCS [11]. В большинстве проектов при разработке используется стандарт Git, разработанный основателем Linux  Линусом Торвальдсом. Однако при разработке игр, помимо непосредственно программного кода, также необходимо контролировать версии т.н. «ассетов»  медиаконтент, используемый в игре: аудио, видео-контент, различные JSON-файлы диалогов и прочее. Для этого Unity разработали собственную VCS, которая гораздо более оптимизирована под работу с таким типом контента, чем вышеупомянутый Git.
Помимо движка, ЯП и VCS, одним из ключевых инструментов является IDE  интегрированная среда разработки. В большинстве случаев при работе с C# используется Visual Studio, однако выбор ПО JetBrains Rider [12] оказался более предпочтительным вариантом.
Данное ПО от создателей IntelliJ IDEA является более подходящим, поскольку в нём гораздо больше инструментов для работы с Unity, более минималистичный и визуально приятный UI, а также Rider предоставляет бесплатную лицензию на некоммерческие проекты и проекты, создаваемые по студенческому пакету программ от JetBrains.
Прежде чем остановиться на Unity, был проведён сравнительный анализ трёх наиболее распространённых игровых движков: Unity, Unreal Engine [13] и Godot [14]. Каждый из них обладает собственной экосистемой, философией разработки и целевой аудиторией, что делает выбор между ними принципиальным решением на этапе проектирования.
Unreal Engine — движок компании Epic Games, разработанный в 1998 году и с тех пор ставший стандартом в AAA-разработке. Основным языком программирования является C++, хотя движок также поддерживает визуальную систему скриптинга Blueprints (рис. 1.1), позволяющую создавать логику без написания кода. Unreal Engine известен исключительно высоким качеством рендеринга: технология Nanite обеспечивает виртуализированную геометрию с детализацией кинематографического уровня, а Lumen реализует полностью динамическое глобальное освещение в реальном времени.

 2 Проектирование и программная реализация игровых механик симулятора CrypteX

Данная глава затрагивает вопросы проектирования архитектуры ПО, а также программную реализацию алгоритмов шифрования и игровых механик.
В процессе реализации игровых механик был использован Unity UI Toolkit [15]  новейший инструментарий от Unity, который позволяет настраивать интерфейс при помощи UXML-разметки. В отличие от Canvas, Toolkit является гораздо более гибким в настройке инструментом, сочетающим в себе все преимущества текстовой вёрстки и ООП-составляющей движка.

2.1 Архитектура приложения

Проектирование архитектуры приложения строится на основных принципах ООП и правилах SOLID. В первую очередь была разработана система, позволяющая создавать уровни, не изменяя при этом «Core-механики»  поведение игры, вложенное в основу геймплея и установленное на этапе проектирования.
Каждый скрипт, отвечающий за обработку игры конкретного шифра, является модульным и заменяемым. Для создания нового шифра достаточно UXML-вёрстки уровня, прописать класс для обработки механик и указать «Win condition» и начальные условия в LevelManager.
Все скрипты, отвечающие за обработку конкретных уровней расположены в директории Assets\Scripts\Gameplay, а основные управляющие классы в Assets\Scripts\Managers.
Такое разделение кода обеспечивает слабую связность компонентов между собой. Менеджеры являются координаторами, которые сообщают необходимые данные игровым классам и напрямую взаимодействуют с движком, а скрипты уровней полностью инкапсулируют всю логику алгоритмов. Это разделение позволяет менять криптографические алгоритмы, не меняя базовых механик.
Для решения задач масштабируемости и управления состоянием в проекте применены следующие паттерны проектирования:
 Singleton (Одиночка): используется для класса GameManager (рис. 2.1). Гарантирует наличие единственного экземпляра менеджера состояния игры во время выполнения. Это критично для реализации глобального события onStateChanged, позволяющего подписанным компонентам (UI, Audio, Input) реагировать на смену контекста без прямой связи между ними;
 Strategy (Стратегия): Применен для абстрагирования криптографических алгоритмов. Каждый скрипт, обрабатывающий конкретный шифр, является независимым модулем. Менеджеры взаимодействуют с алгоритмами через единый интерфейс или базовый класс (в зависимости от вашей реализации), что позволяет динамически подгружать криптографические модули по индексу уровня. Это гарантирует принцип открытости/закрытости: добавление нового шифра не требует изменения кода менеджеров.
 Template Method (Шаблонный метод): Реализован в базовом классе BaseManager. Определяет скелет алгоритма инициализации системы, делегируя шаги реализации подклассам. Например, метод Init() последовательно вызывает инициализацию звуковой, диалоговой и UI-систем, позволяя каждому менеджеру настроить свой процесс старта независимо от других;
 State Machine (Машина состояний): управляет жизненным циклом приложения. Переходы между состояниями (MainMenu, LevelSelect, Hacking, Paused, InDialogue, LevelEnding) контролируются через событийную модель. Это устраняет необходимость в сложных условных конструкциях (if-else) и обеспечивает предсказуемое поведение системы при переключении экранов.
Приложение разделено на три логических слоя:
 слой управления (Management Layer): инкапсулирует глобальное состояние приложения, управление ресурсами и координацию между системами. Реализован через классы-менеджеры (GameManager, UIManager, LevelManager);
 слой игровой логики (Gameplay Layer): содержит модульную реализацию криптографических алгоритмов. Каждый алгоритм инкапсулирован в отдельный класс, что позволяет добавлять новые шифры без изменения базового кода;
 слой представления (Presentation Layer): отвечает за визуализацию интерфейса и взаимодействие с пользователем. Реализован на базе Unity UI Toolkit с использованием UXML и USS для обеспечения производительности и гибкости верстки.

2.2 Проектирование игровых механик

На этапе проектирования основной задачей было создать набор механик, которые одновременно передают теорию шифрования и удерживают внимание через игровой процесс. Концепция строилась вокруг принципа «попробуй — разберись»: игрок должен осваивать алгоритмы через практику, а не через чтение теории. Это определило структуру уровней, способы взаимодействия с интерфейсом и логику обратной связи.
Игровой процесс проектировался как последовательность тематических зон, каждая из которых посвящена определённому классу шифров. Чтобы избежать резкого скачка сложности, была спроектирована плавная кривая обучения. Первые уровни ориентировались на моношифры (например, Цезарь или Атбаш), где механика ввода была максимально упрощена. По мере прохождения вводились многоэтапные задачи (протокол обмена ключами Шамира, RSA), требующие от игрока не только применения знания, но и работы с несколькими состояниями системы.
Для контроля темпа на ранних этапах проектировалась система «демонстрационных режимов». В них игрок мог увидеть, как работает игровая механика, без необходимости самостоятельно вводить данные. Это позволило снизить порог входа и сосредоточиться на понимании логики, а не на механике взаимодействия.
Изначально концепт уровней предполагал нетипичный способ ввода: буквы в текстовых полях должны были набираться наведением курсора мыши на соответствующие элементы интерфейса. На этапе создания прототипа стало очевидно, что такой подход нарушает динамику геймплея. Медленные переходы между точками клика создавали искусственное замедление там, где оно не требовалось по смыслу задачи.
В процессе проектирования механика была изменена: ввод унифицирован со стандартным паттерном (клавиатура + мышь для навигации). Это решение позволило:
 убрать технические барьеры, отвлекающие от криптографической логики;
 сохранить высокую сложность задач как основной вызов для игрока;
 обеспечить плавный геймплей без прерываний на неочевидные элементы управления.
В диалогах проектировалась система пошагового объяснения принципов работы алгоритмов. Текстовые блоки были структурированы так, чтобы игрок получал всю необходимую информацию, а после  приступал к уровню.
Проектирование сложности шло через призму вызова. Игровые механики намеренно не упрощались: головоломки сохраняли свою исходную криптостойкость, но адаптировались под игровой формат через:
 визуализацию ключевых параметров (например, отображение необходимых битов для текущего этапа);
 возможность возврата к уже пройденным уровням на случай, если необходимые для текущего уровня навыки были забыты.
К завершению проектирования все механики были зафиксированы в виде спецификации взаимодействия. Основные проектные параметры:
 структура уровней: линейная прогрессия с постепенным усложнением типов шифров и введением многоэтапных задач;
 ввод данных: унифицированный шаблон, отказ от нетипичных паттернов ради сохранения динамики;
 обучающий компонент: встроенная визуализация алгоритмов, пошаговые объяснения в диалогах;

Понятие Level-дизайна охватывает широкий спектр практик разработки игр. Правильный левел-дизайн использует нарратив уровня для создания нативного игрового пути и интуитивно понятных игровых механик. Некоторые из практик гейм-дизайна, упомянутых ранее, также являются частью левел-дизайна: снижение TTFG, использование звуковых эффектов и фонового музыкального сопровождения, использование единой стилистике в интерфейсе и т.д.
В первую очередь, основой левел-дизайна является показатель сложности каждого конкретного уровня: то, насколько низкая/высокая сложность уместна в указанном контексте, сколько времени в среднем занимает прохождение уровня и насколько эта сложность обусловлена реальной сложностью шифра. Уровни выстроены одновременно в соответствие актуальности шифров (от неактуальных к актуальным) и сложности каждого отдельно взятого метода. Такой подход позволяет планомерно обучить игрока необходимым механикам, не вынуждая его использовать сторонние источники для поиска подсказок и ответов.
К левел-дизайну также относится весь UI, используемый на уровнях. В играх, не основанных только на интерфейсе, к этому также можно отнести расположение и стилистику объектов на сцене (как 2D, так и 3D-проекты).
На уровнях 1, 6 и 11 музыкальное сопровождение изменяется: чем дальше продвигается игрок по уровням, тем более напряжённая, энергичная и нагнетающая музыка начинает играть на фоне. Это обусловлено тем, что такой подход подсознательно создаёт у игрока ощущение прогресса и роста навыков, что подпитывает его интерес к завершению игры до конца. Также изменение музыкального сопровождения отражает сюжетные изменения: чем дальше заходит в своей работе Алекс (протагонист сюжетной линии)  тем опаснее это становится как для агентства, в котором он работает, так и для него самого. Такое решение создаёт сильную эмоциональную связь между игроком и протагонистом, ещё сильнее погружая игрока в историю и игровую вселенную.

2.6 Интеграция аудио и визуальных эффектов

Интеграция визуальных и аудиальных ассетов является одним из ключевых аспектов создания игрового наполнения. В играх, где весь игровой процесс построен на UI музыкальное сопровождение, звуковые и визуальные эффекты берут на себя гораздо больше внимания: отсутствует «осязаемый» мир, интерактивные объекты, неигровые персонажи (NPC) и т.д.
Для создания фонового музыкального сопровождения была использована модель Lyria 3 (используемая в Gemini 3), после чего полученные аудиофайлы были дополнительно обработаны в программе FL Studio 25 [18].
Звуковые эффекты нажатия и наведения на кнопки также были записаны и обработаны в ПО FL Studio 25. Звук нажатия на кнопку был записан на конденсаторный микрофон, используя звук нажатия на кнопку механической клавиатуры. После чего указанный звук при помощи плагина FL Studio Effector был изменён для соответствия сеттингу «Киберпанка».
Полученный звук также был растянут во времени для получения второго звукового эффекта: наведения на кнопку. Замедление звука создаёт искажение его «питча»  изменение высоты звука в сторону повышения при сжатии аудиофайла и в сторону понижения при его растягивании.

Каждое приложение и каждая игра проходят этап тестирования. На этом этапе выявляются основные и второстепенные недочёты, особенности, баги, сильные и слабые стороны разработанного продукта. 3.1 Методология тестирования

Методология тестирования включает в себя комплекс действий для отладки, тестирования и анализа готового или близкого к готовой форме продукта:
 ручное тестирование  проверка работоспособности определённых механик на этапе разработки;
 функциональное тестирование  проверка работоспособности и ожидаемого поведения приложения;
 пользовательское тестирование  получение обратной связи от игроков, ранее не участвовавших в разработке;
 автоматическое тестирование  использование методов различных классов для тестирования ожидаемого поведения игровых механик.
Автоматическое тестирование не было применено, так как игровая логика построена преимущественно на пользовательском интерфейсе и визуальной обратной связи. Игры, построенные на UI и не имеющие большого количества механик, гораздо быстрее и проще тестировать вручную, чем использовать для этого автоматизацию.
Для упрощения тестирования также были разработаны несколько механик:
 чит-консоль  позволяет использовать такие команды, как: unlock, erase, fps, credits для управления прогрессом и получения дополнительной информации об игре. Вызывается при нажатии на [`]/[Ё];
 использование директивы препроцессора #if UNITY_EDITOR для открытия всех 15 уровней при нахождении в редакторе Unity для ускорения процесса ручного тестирования;
 использование метода Debug.Log для вывода отладочной информации (например, успешная инициализация аудио-менеджера).
Выбор указанной методологии тестирования обусловлен небольшой выборкой тестировщиков и фактором разработки приложения в одиночку. При разработке без команды гораздо практичнее создавать удобные инструменты для конкретного разработчика, чем проектировать громоздкую систему тестирования, которой будет пользоваться один человек, не имея на то необходимости.

4.5 Акт III — Современная криптография (уровни 11–15)

Третий акт посвящён современным криптографическим примитивам: XOR-операциям, блочным шифрам, хэш-функциям, кодам аутентификации и асимметричным алгоритмам. Музыкальное сопровождение меняется ещё раз — атмосфера становится максимально напряжённой, соответствуя кульминации сюжета.
Уровень 11: XOR (рис. 4.13). Уровень XOR состоит из трёх этапов, последовательно демонстрирующих применение операции исключающего ИЛИ к различным типам данных: двоичным строкам, десятичным числам и ASCII-символам. Встроенный конвертер позволяет переводить числа между двоичной и десятичной системами прямо в интерфейсе уровня, исключая необходимость сторонних инструментов.

 

Рисунок 4.13  Уровень 11 — XOR, третий этап

Уровень 12: Simplified DES (S-DES). S-DES является упрощённой учебной версией алгоритма DES. Уровень (рис. 4.14) разбит на четыре шага, соответствующих основным операциям алгоритма: перестановка ключа P10, начальная перестановка IP, расширение EP и финальное XOR-сложение. На каждом шаге игрок вводит двоичную строку — результат соответствующего преобразования. Такой формат позволяет прочувствовать внутреннюю структуру блочного шифра без необходимости реализовывать его целиком.
Уровень 13: Хэширование MD5 (рис. 4.15). Уровень моделирует атаку по словарю на хэшированный пароль. Игроку предъявляется целевой хэш и словарь из шести возможных паролей. При вводе каждого варианта в поле интерфейс в реальном времени вычисляет хэш введённой строки и отображает его рядом с целевым — при совпадении оба хэша подсвечиваются зелёным. Такой подход наглядно объясняет, почему хранение паролей в открытом виде опасно, а словарные атаки эффективны против слабых паролей.

Уровень 14: Код аутентификации (MAC). Механика уровня (рис. 4.16) построена на игре «быки и коровы»: игрок пытается угадать секретный цифровой ключ, вводя варианты и получая обратную связь в формате «точно: N | смещено: M». При каждом вводе интерфейс вычисляет псевдо-MAC и сравнивает его с целевым значением. Полное совпадение всех цифр ключа означает успешную «синхронизацию» MAC и открывает доступ к следующему уровню.

Игроку предъявляется открытый ключ (N=143, e=7) и зашифрованный архив. После успешного ввода запускается анимация дешифровки (рис. 4.18): содержимое архива поочерёдно мигает между шифртекстом и открытым текстом, после чего финальное сообщение отображается полностью.

using UnityEngine;
using UnityEngine.Events;
namespace Managers
{
    public class GameManager : BaseManager
    {
        public static GameManager Instance { get; private set; }
        public GameState State { get; private set; } = GameState.MainMenu;
        public UnityEvent<GameState> onStateChanged;
        public LevelManager LevelManager { get; private set; }
        public DialogueManager DialogueManager { get; private set; }
        public UIManager UIManager { get; private set; }
        public AudioManager AudioManager { get; private set; }
        private string ConfigPath => System.IO.Path.Combine(Application.persistentDataPath, "config.json");
        [System.Serializable]
        public class GameConfig
        {
            public int LastLevel = 1;
            public float VolumeBGM = 1.0f;
            public float VolumeSFX = 1.0f;
        }
        public GameConfig Config { get; private set; } = new GameConfig();
        #if UNITY_EDITOR
        private const bool TEST_MODE = true;
        private const int TEST_LEVELS = 15;
        #else
        private const bool TEST_MODE = false;
        #endif
        private GameState _prePauseState = GameState.Hacking;
        private void Start()
        {
            Init();
        }
        private void Update()
        {
            if (UnityEngine.InputSystem.Keyboard.current != null && UnityEngine.InputSystem.Keyboard.current.escapeKey.wasPressedThisFrame)
            {
                if (State == GameState.Hacking || State == GameState.InDialogue)
                {
                    _prePauseState = State;
                    ChangeState(GameState.Paused);
                }
                else if (State == GameState.Paused)
                {
                    ChangeState(_prePauseState);
                }
            }
        }
        private void Awake()
        {
            if (Instance != null && Instance != this)
            {
                Destroy(gameObject);
                return;
            }
            Instance = this;
            
            transform.SetParent(null);
            DontDestroyOnLoad(gameObject);
            
            if (LevelManager == null) LevelManager = FindFirstObjectByType<LevelManager>();
            if (DialogueManager == null) DialogueManager = FindFirstObjectByType<DialogueManager>();
            if (UIManager == null) UIManager = FindFirstObjectByType<UIManager>();
            if (AudioManager == null)
            {
                AudioManager = FindFirstObjectByType<AudioManager>();
                if (AudioManager == null)
                {
                    var audioObj = new GameObject("AudioManager");
                    audioObj.transform.SetParent(this.transform);
                    AudioManager = audioObj.AddComponent<AudioManager>();
                }
            }
            if (gameObject.GetComponent<CheatConsole>() == null)
            {
                gameObject.AddComponent<CheatConsole>();
            }
        }
        public override void Init()
        {
            LoadConfig();
            #if UNITY_EDITOR
            if (TEST_MODE)
            {
                Config.LastLevel = TEST_LEVELS;
                SaveConfig();
                Debug.Log($"TEST MODE: Unlocked all {TEST_LEVELS} levels");
            }
            #endif
            LoadLastLevel();
            LevelManager?.Init();
            DialogueManager?.Init();
            UIManager?.Init();
            AudioManager?.Init();
        }
        public void LoadConfig()
        {
            try
            {
                if (System.IO.File.Exists(ConfigPath))
                {
                    string json = System.IO.File.ReadAllText(ConfigPath);
                    JsonUtility.FromJsonOverwrite(json, Config);
                }
            }
            catch (System.Exception e)
            {
                Debug.LogError($"Failed to load config: {e.Message}");
            }
        }
        public void SaveConfig()
        {
            try
            {
                string json = JsonUtility.ToJson(Config, true);
                System.IO.File.WriteAllText(ConfigPath, json);
            }
            catch (System.Exception e)
            {
                Debug.LogError($"Failed to save config: {e.Message}");
            }
        }
        public void ChangeState(GameState newState)
        {
            if (State == newState) return;
            State = newState;
            onStateChanged?.Invoke(State);
        }
        public void ResumeFromPause()
        {
            if (State == GameState.Paused)
            {
                ChangeState(_prePauseState);
            }
        }
        public int GetLastLevel()
        {
            return Config.LastLevel;
        }
        public void SaveLevel(int level)
        {
            if (level > GetLastLevel())
            {
                Config.LastLevel = level;
                SaveConfig();
                Debug.Log($"Saved level: {level}");
            }
        }
        public void EraseProgress()
        {
            Config.LastLevel = 1;
            SaveConfig();
            LoadLastLevel();
            Debug.Log("Progress erased. Returning to level 1.");
        }
        private void LoadLastLevel()
        {
            int lastLevel = GetLastLevel();
            LevelManager?.SetLevel(lastLevel);
        }
    }
    public enum GameState
    {
        MainMenu,
        LevelSelect,
        Hacking,
        Paused,
        InDialogue,
        LevelEnding
    }
}

namespace Gameplay

    public class CaesarHackMinigame
    {
        private VisualElement _root;
        private Label _centerLabel;
        private Label _topLabel;
        private Label _bottomLabel;
        
        private string _originalEncryptedText;
        private string _targetDecryptedText;
        private Action _onSuccess;
        
        private int _currentShift = 0;
        private bool _isAnimating;

        private Button _upBtn;
        private Button _downBtn;

        public CaesarHackMinigame(VisualElement root, string encryptedText, string targetDecryptedText, Action onSuccess)
        {
            _root = root;
            _originalEncryptedText = encryptedText;
            _targetDecryptedText = targetDecryptedText;
            _onSuccess = onSuccess;

            BindElements();
            UpdateTextImmediate();
        }

        private void BindElements()
        {
            _centerLabel = _root.Q<Label>("EncryptedText");
            _topLabel = _root.Q<Label>("RightUpText");
            _bottomLabel = _root.Q<Label>("LeftDownText");

            _upBtn = _root.Q<Button>("RightUpButton");
            _downBtn = _root.Q<Button>("LeftDownButton");
            
            _upBtn?.RegisterCallback<ClickEvent>(evt => OnShiftInput(1));
            _downBtn?.RegisterCallback<ClickEvent>(evt => OnShiftInput(-1));
        }

        public void OnShiftInput(int direction)
        {
            if (_isAnimating) return;
            GameManager.Instance.StartCoroutine(AnimateShift(direction));
        }

        private void UpdateTextImmediate()
        {
            if (_centerLabel == null) return;
            _centerLabel.text = ApplyShift(_originalEncryptedText, _currentShift);
            _topLabel.text = ApplyShift(_originalEncryptedText, _currentShift + 1);
            _bottomLabel.text = ApplyShift(_originalEncryptedText, _currentShift - 1);
        }

        private IEnumerator AnimateShift(int direction)
        {
            _isAnimating = true;

            float distance = _centerLabel.resolvedStyle.height; 
            if (distance <= 1f) distance = 100f;

            float duration = 0.5f;
            float elapsed = 0f;

            int visualDir = direction;
            
            while (elapsed < duration)
            {
                elapsed += Time.deltaTime;
                float t = Mathf.Clamp01(elapsed / duration);
                float smoothT = Mathf.SmoothStep(0f, 1f, t);
                
                float currentY = Mathf.Lerp(0, visualDir * distance, smoothT);
                
                SetTranslate(_centerLabel, currentY);
                SetTranslate(_topLabel, currentY);
                SetTranslate(_bottomLabel, currentY);
                
                yield return null;
            }

            _currentShift += direction;
            
            SetTranslate(_centerLabel, 0);
            SetTranslate(_topLabel, 0);
            SetTranslate(_bottomLabel, 0);
            
            UpdateTextImmediate();

            _isAnimating = false;
            CheckWin();
        }

        private void SetTranslate(VisualElement e, float y)
        {
            if (e == null) return;
            e.style.translate = new Translate(0, y, 0);
        }

        private string ApplyShift(string text, int shiftAmount)
        {
            const string Alphabet = "АБВГДЕЁЖЗИЙКЛМНОПРСТУФХЦЧШЩЪЫЬЭЮЯ";
            char[] buffer = text.ToCharArray();
            int n = Alphabet.Length;

            for (int i = 0; i < buffer.Length; i++)
            {
                char c = buffer[i];
                int index = Alphabet.IndexOf(char.ToUpper(c));

                if (index != -1)
                {
                    int newIndex = (index + shiftAmount) % n;
                    if (newIndex < 0) newIndex += n;

                    char newChar = Alphabet[newIndex];
                    buffer[i] = char.IsLower(c) ? char.ToLower(newChar) : newChar;
                }
                else if (char.IsLetter(c) && ((c >= 'A' && c <= 'Z') || (c >= 'a' && c <= 'z')))
                {
                    char d = char.IsUpper(c) ? 'A' : 'a';
                    buffer[i] = (char)((((c + shiftAmount) - d) % 26 + 26) % 26 + d);
                }
            }
            return new string(buffer);
        }

        private void CheckWin()
        {
            if (_centerLabel.text == _targetDecryptedText)
            {
                if (_upBtn != null) _upBtn.style.display = DisplayStyle.None;
                if (_downBtn != null) _downBtn.style.display = DisplayStyle.None;
                
                GameManager.Instance.StartCoroutine(DelaySuccessCall());
            }
        }
        
        private IEnumerator DelaySuccessCall()
        {
            yield return new WaitForSeconds(1.5f);
            _onSuccess?.Invoke();
        }
        
        public IEnumerator AutoSolve(string targetText)
        {
            int targetShift = -5;

            int currentShift = _currentShift;
            int diff = targetShift - currentShift;
            int length = 33;

            int forwardSteps = (diff + length) % length;
            int backwardSteps = (length - forwardSteps) % length;

            int direction = 1;
            int steps = forwardSteps;

            if (backwardSteps < forwardSteps && backwardSteps > 0)
            {
                direction = -1;
                steps = backwardSteps;
            }

            Debug.Log($"AutoSolve: Current={currentShift}, Target={targetShift}, Steps={steps}, Dir={direction}");

            for (int i = 0; i < steps; i++)
            {
                if (_centerLabel.text == targetText) break;
                yield return AnimateShift(direction);
                yield return new WaitForSeconds(0.2f);
            }

            yield return new WaitForSeconds(0.5f);
        }
    }

using UnityEngine;

namespace Managers
{
    public class AudioManager : BaseManager
    {
        private AudioSource _toneSource;
        private AudioSource _bgmSource;
        private AudioSource _sfxSource;
        private string _currentBGMFileName = string.Empty;
        private System.Collections.Generic.Dictionary<string, AudioClip> _sfxCache = new System.Collections.Generic.Dictionary<string, AudioClip>();
        private System.Collections.Generic.Dictionary<string, float> _sfxLastPlayed = new System.Collections.Generic.Dictionary<string, float>();
        private AudioClip _sineWaveClip;

        private float _volumeBGM = 1.0f;
        private float _volumeSFX = 1.0f;

        public float VolumeBGM 
        {
            get => _volumeBGM;
            set 
            {
                _volumeBGM = Mathf.Clamp01(value);
                if (_bgmSource != null) _bgmSource.volume = _volumeBGM * 0.5f;
                if (GameManager.Instance != null && GameManager.Instance.Config != null)
                {
                    GameManager.Instance.Config.VolumeBGM = _volumeBGM;
                    GameManager.Instance.SaveConfig();
                }
            }
        }

        public float VolumeSFX 
        {
            get => _volumeSFX;
            set 
            {
                _volumeSFX = Mathf.Clamp01(value);
                if (_sfxSource != null) _sfxSource.volume = _volumeSFX;
                if (_toneSource != null) _toneSource.volume = _volumeSFX;
                if (GameManager.Instance != null && GameManager.Instance.Config != null)
                {
                    GameManager.Instance.Config.VolumeSFX = _volumeSFX;
                    GameManager.Instance.SaveConfig();
                }
            }
        }

        public override void Init()
        {
            if (GameManager.Instance != null && GameManager.Instance.Config != null)
            {
                _volumeBGM = GameManager.Instance.Config.VolumeBGM;
                _volumeSFX = GameManager.Instance.Config.VolumeSFX;
            }
            else
            {
                _volumeBGM = 1.0f;
                _volumeSFX = 1.0f;
            }

            if (_toneSource == null)
            {
                _toneSource = gameObject.AddComponent<AudioSource>();
                _toneSource.playOnAwake = false;
                _toneSource.loop = true;
                _toneSource.volume = _volumeSFX;
            }

            if (_bgmSource == null)
            {
                _bgmSource = gameObject.AddComponent<AudioSource>();
                _bgmSource.playOnAwake = false;
                _bgmSource.loop = true;
                _bgmSource.volume = _volumeBGM * 0.5f;
            }

            if (_sfxSource == null)
            {
                _sfxSource = gameObject.AddComponent<AudioSource>();
                _sfxSource.playOnAwake = false;
                _sfxSource.loop = false;
                _sfxSource.volume = _volumeSFX;
            }

            if (_sineWaveClip == null)
            {
                _sineWaveClip = CreateSineWaveClip(440, 1.0f);
                _toneSource.clip = _sineWaveClip;
            }
        }

        public void PlayTone(float pitch = 1.0f)
        {
            if (_toneSource == null) Init();
            
            _toneSource.pitch = pitch;
            if (!_toneSource.isPlaying)
            {
                _toneSource.Play();
            }
        }

        public void StopTone()
        {
            if (_toneSource != null && _toneSource.isPlaying)
            {
                _toneSource.Stop();
            }
        }

        public void PlayBGM(string fileName)
        {
            if (_bgmSource == null) Init();
            if (_bgmSource == null) return;
            
            if (_bgmSource.isPlaying && _currentBGMFileName == fileName) return;
            
            _currentBGMFileName = fileName;
            StopBGM();
            StartCoroutine(LoadBGMCoroutine(fileName));
        }

        public void StopBGM()
        {
            if (_bgmSource != null && _bgmSource.isPlaying)
            {
                _bgmSource.Stop();
            }
        }

        public void PlaySFX(string fileName, bool preventOverlap = false)
        {
            if (_sfxSource == null) Init();
            if (_sfxSource == null) return;
            
            if (_sfxCache.TryGetValue(fileName, out AudioClip clip))
            {
                if (preventOverlap)
                {
                    if (_sfxLastPlayed.TryGetValue(fileName, out float lastTime))
                    {
                        if (Time.unscaledTime - lastTime < clip.length) return;
                    }
                    _sfxLastPlayed[fileName] = Time.unscaledTime;
                }
                _sfxSource.PlayOneShot(clip);
            }
            else
            {
                StartCoroutine(LoadSFXCoroutine(fileName, true, preventOverlap));
            }
        }

        public void PreloadSFX(string fileName)
        {
            if (!_sfxCache.ContainsKey(fileName))
            {
                StartCoroutine(LoadSFXCoroutine(fileName, false, false));
            }
        }

        private System.Collections.IEnumerator LoadSFXCoroutine(string fileName, bool playOnLoad, bool preventOverlap)
        {
            string url = System.IO.Path.Combine(Application.streamingAssetsPath, fileName).Replace("\\", "/");
            if (!url.Contains("://"))
            {
                if (url.StartsWith("/"))
                    url = "file://" + url;
                else
                    url = "file:///" + url;
            }
            
            UnityEngine.AudioType audioType = UnityEngine.AudioType.UNKNOWN;
            string lowerUrl = url.ToLower();
            if (lowerUrl.EndsWith(".ogg")) audioType = UnityEngine.AudioType.OGGVORBIS;
            else if (lowerUrl.EndsWith(".mp3")) audioType = UnityEngine.AudioType.MPEG;
            else if (lowerUrl.EndsWith(".wav")) audioType = UnityEngine.AudioType.WAV;

            using (UnityEngine.Networking.UnityWebRequest www = UnityEngine.Networking.UnityWebRequestMultimedia.GetAudioClip(url, audioType))
            {
                yield return www.SendWebRequest();

                if (www.result == UnityEngine.Networking.UnityWebRequest.Result.Success)
                {
                    AudioClip clip = UnityEngine.Networking.DownloadHandlerAudioClip.GetContent(www);
                    if (clip != null)
                    {
                        _sfxCache[fileName] = clip;
                        if (playOnLoad && _sfxSource != null)
                        {
                            bool shouldPlay = true;
                            if (preventOverlap)
                            {
                                if (_sfxLastPlayed.TryGetValue(fileName, out float lastTime))
                                {
                                    if (Time.unscaledTime - lastTime < clip.length)
                                        shouldPlay = false;
                                }
                                if (shouldPlay)
                                    _sfxLastPlayed[fileName] = Time.unscaledTime;
                            }
                            if (shouldPlay)
                                _sfxSource.PlayOneShot(clip);
                        }
                    }
                }
            }
        }

        private System.Collections.IEnumerator LoadBGMCoroutine(string fileName)
        {
            string url = System.IO.Path.Combine(Application.streamingAssetsPath, fileName).Replace("\\", "/");
            if (!url.Contains("://"))
            {
                if (url.StartsWith("/"))
                    url = "file://" + url;
                else
                    url = "file:///" + url;
            }
            
            Debug.Log($"[AudioManager] Loading BGM from url: {url}");
            
            UnityEngine.AudioType audioType = UnityEngine.AudioType.UNKNOWN;
            string lowerUrl = url.ToLower();
            if (lowerUrl.EndsWith(".ogg")) audioType = UnityEngine.AudioType.OGGVORBIS;
            else if (lowerUrl.EndsWith(".mp3")) audioType = UnityEngine.AudioType.MPEG;
            else if (lowerUrl.EndsWith(".wav")) audioType = UnityEngine.AudioType.WAV;

            using (UnityEngine.Networking.UnityWebRequest www = UnityEngine.Networking.UnityWebRequestMultimedia.GetAudioClip(url, audioType))
            {
                yield return www.SendWebRequest();

                if (www.result == UnityEngine.Networking.UnityWebRequest.Result.ConnectionError || www.result == UnityEngine.Networking.UnityWebRequest.Result.ProtocolError)
                {
                    Debug.LogError($"Error loading BGM {fileName}: {www.error} URL: {url}");
                }
                else
                {
                    AudioClip clip = UnityEngine.Networking.DownloadHandlerAudioClip.GetContent(www);
                    if (clip != null)
                    {
                        Debug.Log($"[AudioManager] Successfully loaded {fileName}, length: {clip.length}");
                        _bgmSource.clip = clip;
                        _bgmSource.Play();
                    }
                    else
                    {
                        Debug.LogError("[AudioManager] BGM AudioClip is null after loading.");
                    }
                }
            }
        }

        private AudioClip CreateSineWaveClip(int frequency, float durationSec)
        {
            int sampleRate = 44100;
            int sampleCount = (int)(sampleRate * durationSec);
            float[] data = new float[sampleCount];

            for (int i = 0; i < sampleCount; i++)
            {
                float t = i / (float)sampleRate;
                data[i] = Mathf.Sin(2 * Mathf.PI * frequency * t);
            }

            AudioClip clip = AudioClip.Create("SineWave", sampleCount, 1, sampleRate, false);
            clip.SetData(data, 0);
            return clip;
        }
    }
